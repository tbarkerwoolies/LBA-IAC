## How Odessa interacts with this stack

- Odessa manages identity (AAD groups, IDConnect roles, role assignments)
  and the foundational Azure resources (RG, NSG/ASGs, UAMI, Key Vault,
  Private DNS) for each AS listed above.
- Each AS has its own Terraform state — runs triggered from one AS's
  subdir don't touch sibling ASes.
- This Terraform configuration is **owned by your team** — add the
  application resources you need on top of the Odessa-managed foundation.
- TFC workspace variables (TLA, APPLICATION_SERVICE_ID, KEY_VAULT_URL, …)
  are managed by Odessa. Do not commit `.tfvars` files; request variable
  changes via the Odessa API.

## Edit policy

- `main.tf` and this README are scaffolded on first reconcile.
  Subsequent stack reconciles leave them alone (`overwriteOnCreate=false`),
  so your edits persist. You are free to add additional `*.tf` files in
  any AS subdirectory.
- `backend.tf` is **system-owned** and re-rendered on every reconcile
  (`overwriteOnCreate=true`). Do not edit it — your changes will be lost
  on the next reconcile. Request backend changes via the Odessa API.
